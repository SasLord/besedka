# Wave 2.2 — чат в UI (отчёт)

**Дата:** 2026-10-30 · **Коммит:** `08827a0` · **Статус:** DONE

## Срез (Accept из PLAN.md 2.2)
Пользователь открывает комнату → видит историю (свежие), печатает и отправляет, старые сообщения подгружаются (пагинация), новые сообщения других видны без перезагрузки страницы (polling).

## Что сделано

### Бэкенд (минимально, только недостающее)
- `GET /api/v1/users` (AuthedUser) → `{"users":[{"id","display_name"},...]}` — каталог пользователей для имён отправителей (пригодится и в 2.3 read receipts).
- `Db::list_users()` в infra: `SELECT id, display_name FROM users ORDER BY display_name`; `display_name` падает на `username`, если не задан (т.е. у парольных регистраций имя = логин, реальное ФИО даёт только AD/SSO).

### UI (главная часть)
- Новый компонент `ui/src/lib/components/RoomChat.svelte` + секция чата в `App.svelte`.
- Клик по комнате → заголовок (название + бейдж вида) + список сообщений (имя, время, текст).
- Имена: `fetchUsers()` один раз после логина (карта id→display_name), своя — «Вы». **Live-каталог:** при каждом тике поллинга, если в новых сообщениях есть незнакомный sender_id — каталог перечитывается (иначе новый участник показывался бы как «Пользователь #N» до перезагрузки).
- Ввод: поле + Enter/кнопка, trim, пустое не шлём; после 201 сообщение добавляется в список (дубликаты по id исключены).
- Пагинация: свежие 50; если их ровно 50 — кнопка «Загрузить ещё» (`before_id` = id самого старшего в списке); при скролле вниз новые не прыгают.
- Live: поллинг `GET /rooms/{id}/messages?limit=…&before_id=<новейшее id>` каждые 3 с, только пока чат открыт и вкладка видна (`visibilitychange`); новые вставляются сверху.
- `api.ts`: тип `Message`, `listMessages(roomId, limit?, beforeId?)`, `postMessage(roomId, text)`, `fetchUsers()`.

## Живая проверка в браузере (сервер :8080)
1. **Пагинация:** в комнате 50 сообщений → кнопка «Загрузить ещё» подтянула старшие (id 1–50 → +50), счётчик 50→100.
2. **Live + имена нового участника:** пользователь `фин` зарегистрирован ПОСЛЕ логина наблюдателя → его пост появился через ~3 с **без перезагрузки**, имя — из каталога (username-fallback), а не «Пользователь #8».
3. **Свой пост:** отправлен, появился сверху, дублей по id нет.

## Известные ограничения (намеренные, для следующих срезов)
- Поллинг 3 с — не WS (WS — если понадобится в 2.3+).
- Пагинация кнопкой, не автоскролл-подгрузкой (кнопка — проще и предсказуемее).
- `display_name` для парольных регистраций = username (ФИО — только AD/SSO; это поведение БД, не баг).
